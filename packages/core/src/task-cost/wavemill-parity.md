# Wavemill parity

Wavemill's cost pipeline (`shared/lib/{session-adapters,execution-economics,workflow-cost,eval-schema}.ts`,
HOK-2958) is the behavioural oracle for this contract. A later migration should be
able to swap Wavemill's implementation for `aggregateTaskCost` and explain every
output difference from this document.

## How the oracle works

1. `wavemill-golden.ts` holds Wavemill's *actual* output. It is generated by
   running Wavemill's real `buildExecutionEconomics` over the matching SDK fixtures
   (`scripts/generate-wavemill-task-cost-golden.mjs`; the file header records the
   Wavemill commit). It is verbatim Wavemill output, camelCase and all.
2. `parity.test.ts` reduces each fixture with `aggregateTaskCost`, projects the
   summary onto Wavemill's session shape, and compares field by field.
3. Each fixture has a `PERMITTED_DIFFERENCES` entry listing the fields allowed to
   differ. The test requires the *actual* differences to equal that list exactly,
   so a new drift and a stale exemption both fail.

To regenerate after a Wavemill change:

```sh
cd "$WAVEMILL" && node "$SDK/scripts/generate-wavemill-task-cost-golden.mjs" "$SDK"
```

Review the diff; a changed golden means Wavemill's behaviour moved.

## Non-differences (the parity floor)

The parity test asserts these hold for every fixture that maps to a Wavemill
session: token totals (null-preserving sums), `actualCostUsd`, `costSource`,
`coverage`, `turnCount`, `modelSegments`, and `estimatedCostUsd`, except where
listed below. Also identical by construction: the availability, coverage, join
confidence, and provider-contract value sets; the cache multipliers (writes 1.25x,
reads 0.1x of input); "unknown model prices to `null`, never a fabricated
value"; and the pricing-table revision (`MODEL_PRICING_AS_OF`).

The `codex-simple` divergence, the `codex-unknown-pricing` /
`partial-usage` `estimatedCostUsd`/`coverage` rows, and the `codex/2` version
drift are Wavemill defects the migration should fix rather than reproduce.
Migrate Wavemill to the SDK behaviour and delete these exemptions. The
`providerContractVersion` drift on every Codex fixture resolves once Wavemill
ships its own double-bill fix and bumps to `codex/2`.

### Contract-level (not exercised by a Wavemill golden)

1. **`cost_source: mixed`.** The SDK adds `mixed` on summaries. Wavemill's
   session enum has three values and says `provider_reported` whenever a session
   actual exists. Map `mixed` to `provider_reported` if a three-valued field is
   required; the `mixed` fixture has no Wavemill counterpart.
2. **Cost basis.** `cost_basis` (`per_token_api` / `subscription` / `unknown`) is
   new. Wavemill has no such flag; add it as an optional column.
3. **Missing vs known-zero.** Both keep `null` for missing counters. The SDK also
   derives `known_zero` per event and per summary; Wavemill only emits
   `known_zero` for an explicit zero-price model. Migration records the marker
   additively.
4. **Coverage across events.** The SDK counts a confirmed-zero event as complete
   when mixed with complete events; Wavemill's `aggregateCoverage` would say
   `partial`. Single-session inputs are unaffected.
5. **Known-zero on a provider zero charge.** An `actual_cost_usd` of `0` yields
   `known_zero` coverage in the SDK; Wavemill reports `complete` (and only sets
   `fieldAvailability.actualCost: known_zero`).
6. **Granularity.** The SDK summarizes per task across sessions; Wavemill emits a
   block per harness and session. `aggregateTaskCost` refuses to mix harnesses
   (`mixed_scope`), so Wavemill's per-harness blocks map onto one summary each.
7. **Provider-reported cost location.** Wavemill carries one session-level
   `actualCostUsd`. The SDK carries it per event and sums. A session total maps to
   a single event, or is split across turns if the source gives per-turn charges.
8. **Segments.** Both use consecutive runs. The SDK's carry usage and cost too.
9. **Float noise.** Wavemill can emit `0.10925000000000001`; the SDK rounds sums
   to nanodollars. The parity comparison uses a `1e-9` tolerance.
10. **`event_ids`.** SDK-only manifest of contributing events; drop on ingest.
11. **Timestamps.** `pricingTimestamp` is the collection time in both
    (`collected_at` in the SDK); Wavemill formats it with milliseconds.

## Pricing tables are inputs, not part of the contract

The parity test feeds Wavemill the SDK's price table, so it proves the two
pipelines *compute* the same way. It does not prove the two *tables* agree. They
do not: as of Wavemill `a2d1cd6b`, its default table (`config-sync.ts`) prices
`claude-sonnet-5` at $2 / $10 per MTok, and the SDK's `ANTHROPIC_MODEL_PRICING`
at $3 / $15. The `wavemill-parity` fixture therefore uses `claude-opus-4-8` and
`claude-sonnet-4-6`, where both tables agree. Reconcile the tables before
migrating, or pass the SDK's table into Wavemill.

### Codex `codex/1` vs `codex/2`

`codex/1` reflects Wavemill's double-bill: raw `input_tokens` priced at the
input rate while `cached_input_tokens` is a subset, and `reasoning_output_tokens`
added onto `output_tokens` for billing. `codex/2` (HOK-3104) makes the buckets
disjoint on ingest — the Codex adapter subtracts `cached + cache_write` from
`input_tokens` and clamps at zero (`codex_cache_exceeds_input` on underflow) —
and treats `reasoning_tokens` as a reporting-only breakdown of `output_tokens`.
See HOK-3074 EF-3 for the Wavemill side. Historical `codex/1` ledger rows keep
their old meaning; new rows written by this adapter are `codex/2`.
